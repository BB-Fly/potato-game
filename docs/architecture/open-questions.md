# 架构待确认问题

本文档记录实现架构层面需要后续澄清的内容。这些问题不阻塞基础框架搭建，但会影响数据模型、接口稳定性、调试工具和内容生产流程。

## 引擎与技术栈

1. 最终是否确定使用 Godot？如果是，需要确认版本、GDScript/C# 选择、配置格式和资源导入流程。
2. 是否需要支持移动端首发？这会影响输入、性能预算、资源规格、音频压缩和 UI 尺寸。
3. 是否需要战斗回放、录像、排行榜或联网校验？如果需要，固定 tick 和随机数状态要更严格地可回放。

## 战斗规则

1. 玩家、怪物、投射物、区域伤害的碰撞层和碰撞体尺寸尚未定义。
2. 通用受击无敌帧、单伤害源无敌帧的默认时长需要确定。
3. Boss 属性、阶段、技能、召唤物、环境危险、Boss 后是否继续刷怪仍未定义。
4. 精英怪是否进入 Demo，以及精英词缀是否复用 buff 系统，需要确认。
5. 处决触发条件是只依赖破韧，还是允许血量阈值、buff 标记、武器特例共同触发，需要确认。
6. 能量资源的获取方式、上限成长方式、战斗外是否保留，需要确认。

## 数值与公式

1. 伤害公式的最终乘区、加法区、暴击、减伤、防御、攻击倍率之间的精确顺序需要数值设计确认。
2. 属性命名需要统一，例如“近战攻击”和“近战伤害”是否是同一属性。
3. 攻击速度是加快攻击频率、减少攻击间隔，还是作为百分比修正，需要确认。
4. 魔法强度、治疗强度、持续伤害强度是否作为独立属性，需要确认。

## 武器、魔法、强化与融合

1. 武器/魔法融合可转移的词条类型、不可转移规则、冲突规则需要定义。
2. 融合后材料的强化资源返还形式是返还强化石、金币，还是恢复为可用强化次数，需要确认。
3. 强化池、强化品质、强化数值范围、是否允许重复强化同一属性需要确认。
4. 武器技能充能条件需要统一支持哪些类型：时间、击杀、伤害、命中、受击或混合条件。
5. 魔法主动释放是否必须由玩家按键触发，还是可支持自动施法策略，需要确认。

## Buff 与异常状态

1. Demo 首批 buff 清单、标签、叠加模式、最大层数、持续时间、驱散规则需要补齐。
2. 控制抗性、Boss 控制免疫、韧性恢复速度是否存在，需要确认。
3. 光环类 buff 是挂在来源实体上，还是创建独立区域实体，需要确认。
4. 永久道具 buff 在道具被转换或移除时是否需要反向卸载，需要确认。

## 地图、奖励与奇遇

1. 地图允许玩家用鼠标滚轮或手柄回看已揭示的上一层/下一层区域，但回看只读，不允许撤销已选择路线；仍需定义 UI 上如何标记已选择、已完成和未解锁区域。
2. 奇遇事件的数据格式、选项条件、风险收益、剧情文本和效果表达需要定义。
3. 战斗奖励是否允许出现武器/魔法，还是 Demo 固定只有金币和传说道具，需要确认。
4. 第三章的扩展方向会影响章节配置 schema 是否需要提前支持更多路线结构。

## 内容与资源管线

1. 配置权威格式需要确认：JSON、YAML、TOML、表格导出，或引擎原生资源。
2. 美术资源规格需要确认：像素单位、朝向、动画帧率、命名规范、图集策略。
3. 音乐是否需要分层混音、战斗强度分层、Boss 横向切换，需要确认。
4. 多语言是否纳入 Demo。如果纳入，所有显示文本要从本地化表读取。

## 存档与调试

1. Demo 是否需要局中保存和恢复。
2. 是否需要保留失败/胜利后的详细统计。
3. 是否需要提供给策划使用的物品池模拟器和战斗模拟器 UI。
4. 是否需要热重载配置。若需要，运行时配置覆盖和存档兼容要提前设计。
